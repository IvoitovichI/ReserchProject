# Task templates for the agent

Fill only relevant fields. The agent should resolve details from the repository instead of demanding every optional field.

## 1. New gameplay feature

```markdown
Task: Implement <feature>.
Player outcome: <observable result>.
Mode: <all / ResearchObservation / Pilot / Sandbox>.
In scope: <definitions, runtime, UI, telemetry>.
Out of scope: <explicit exclusions>.
Acceptance criteria:
- ...
Research impact: <question/metric/opportunity or none>.
Constraints: <seed, settings, content version>.
```

## 2. Bug report

```markdown
Task: Fix <short symptom>.
Build/content/schema version: ...
Mode and seed: ...
Room/weapon/enemy IDs: ...
Steps:
1. ...
Expected: ...
Actual: ...
Frequency: ...
Logs/video: ...
Do not change: ...
```

## 3. New room

```markdown
Task: Add room <room_id>.
Type/tier/tags: ...
Sockets: ...
Encounter budget/options: ...
Rewards: ...
Secret/clue: ...
Telemetry zones/opportunities: ...
Target clear time: ...
Seed pool: <pilot only / candidate / main study>.
Acceptance: room validator + isolated test + generation batch.
```

## 4. New weapon/enemy/item

```markdown
Task: Add <content type and stable ID>.
Behavioral role: ...
Definition values: ...
Reusable strategy/components: ...
Interactions and edge cases: ...
Telemetry events/denominators: ...
Balance hypothesis: ...
Acceptance tests: ...
```

## 5. Telemetry event

```markdown
Task: Add or revise event <event_name>.
Question answered: ...
Source gameplay fact: ...
Exact trigger: ...
Payload fields and units: ...
Context/stable IDs: ...
Sampling/cardinality: ...
Opportunity denominator: ...
Schema compatibility: ...
Validation/expected derived feature: ...
```

## 6. Refactoring request

```markdown
Task: Refactor <module> because <measurable problem>.
Behavior that must remain identical: ...
Public/serialized contracts to preserve: ...
Allowed migration: ...
Forbidden scope: ...
Characterization tests/evidence: ...
```

## 7. Review request

```markdown
Review <files/module/change> for:
- correctness and lifecycle;
- architecture/dependency direction;
- determinism and frame-rate dependence;
- telemetry semantics/privacy;
- Unity serialization/assets;
- tests and regressions.
Return findings ordered by severity with file/line evidence. Do not modify files unless asked.
```

## 8. Suggested agent handoff format

```markdown
Outcome: <what now works>.
Changed: <files/modules>.
Research/version impact: <none or exact decision>.
Verified: <tests/build/manual checks actually run>.
Not verified: <remaining checks and why>.
Risks/follow-up: <only concrete remaining items>.
```
